# Historical toolchain investigation

The compiler pilot verifies Microsoft C 5.10 using three fresh builds of a fixed C signature probe. Run `tools/compiler/run_pilot.py --check` to rebuild and compare against [the recorded C pilot](../analysis/compiler/c_pilot.json); `--record` explicitly regenerates that tracked evidence. The [MSC 5.10 experiment](../analysis/compiler/msc510-signatures.md) records source/tool hashes, exact OMF code bytes and instruction listings, flags, and near/far return evidence. The probe is not a game-source attribution.

The MASM proof recipe is `tools/compiler/build_proof.py`. It freshly assembles [the shared Cycles display helper](../src/engine/graphics/ega_copy_planes.asm), parses its OMF public symbol and code bytes, and checks the result against manifest-pinned load images. The expected stable receipt is [analysis/compiler/proof.json](../analysis/compiler/proof.json); `--check` rebuilds and compares without changing that tracked receipt. The object and default receipt are written only under ignored `work/compiler/`. MASM 5.10 and the MS-DOS Player are pinned by hashes inside the recipe, and the recipe source itself is fingerprinted in `analysis/compiler/build_proof.sha256`.

That is a strict byte-for-byte source-to-image proof for a 106-byte far-returning routine shared by Cycles EGA, CGA, and Tandy. The exact code match is verified; identifying the bytes as an in-use display helper remains provisional because no incoming far-call site or far-pointer reference is confirmed, and copied or unused support code remains possible. It does not establish the C compiler used by either game. The known 697-byte Circuit/Cycles EGA exact region remains an internal raster-code slice rather than a complete callable routine, so it is separate evidence.
